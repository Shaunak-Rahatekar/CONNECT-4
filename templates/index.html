🧠 Design & Analysis of Algorithms (DAA) Learning Center

Mathematical formulations, recurrence relations, complexity proofs, and empirical analysis matching the Connect-4 codebase.

1. Minimax Recurrence & Zero-Sum Search Formulation Unit II — Divide & Conquer

In two-player zero-sum games of perfect information, optimal play is governed by the Minimax value $V(s)$:

$$V(s) = \max_{a \in \text{Actions}(s)} \min_{a' \in \text{Actions}(s')} V(s'')$$

Depth-Aware Terminal Utility: Faster wins receive higher bonuses ($+1,000,000 + d \times 1,000$) to prioritize shortest victory paths, while unavoidable defeats are delayed ($-1,000,000 - d \times 1,000$).

Complexity: $T(d) = O(b^d)$ time and $S(d) = O(d)$ stack frames via in-place move undoing.

2. Alpha-Beta Pruning Optimization & Cutoff Invariants Unit II & IV — Pruning & Backtracking

Alpha-Beta maintains a dynamic search window $[\alpha, \beta]$ where:

  • $\alpha$ (alpha): The maximum score the maximizing player is guaranteed to achieve.
  • $\beta$ (beta): The minimum score the minimizing player allows the maximizing player to achieve.

Pruning Condition: Whenever any child evaluation satisfies $\beta \le \alpha$, a branch cutoff occurs immediately. At MAX nodes, if $v \ge \beta$, the minimizing ancestor will never choose this path. At MIN nodes, if $v \le \alpha$, the maximizing ancestor already has a superior alternative.

Preservation Proof: Discarded subtrees are mathematically proven to be dominated by already evaluated siblings; thus, $\text{Eval}_{\text{Alpha-Beta}} \equiv \text{Eval}_{\text{Minimax}}$.

Complexity: Worst-case $O(b^d)$ when moves are explored worst-to-best; Best-case $O(b^{d/2})$ under optimal move ordering, dropping the effective branching factor from $b \approx 7$ to $b_{\text{eff}} \approx \sqrt{7} \approx 2.65$.

3. Tactical Move Ordering Heuristic Unit IV — Greedy Heuristics

To approach the theoretical best-case $O(b^{d/2})$, candidate moves are ordered prior to recursion:

  1. Transposition Table Hash Move (+50,000): The best move discovered in previous searches at this state.
  2. Immediate Winning Moves (+10,000): Dropping a disc that immediately completes 4-in-a-row.
  3. Immediate Blocking Moves (+5,000): Columns where the opponent would win on their next turn.
  4. Center-to-Flank Proximity: Columns closer to the center column (Col 4) receive up to +60 bonus points due to participation in more winning lines (col 3 participates in 24 windows vs. col 0/6 in only 3).
4. Memoization, Bound Semantics & Transposition Tables Unit III — Dynamic Programming

Connect-4 game paths form a Directed Acyclic Graph (DAG). Permutations of independent moves reach identical states (transpositions). A Transposition Table caches evaluated subproblems to avoid redundant re-search.

Alpha-Beta Bound Classification:

  • EXACT: Accurate minimax value ($\alpha < v < \beta$).
  • LOWER_BOUND: Beta-cutoff occurred ($v \ge \beta$). True value $\ge v$.
  • UPPER_BOUND: Fail-low ($v \le \alpha$). True value $\le v$.

Depth Invariant: Reused for score cutoff only if $d_{\text{stored}} \ge d_{\text{current}}$. If $d_{\text{stored}} < d_{\text{current}}$, the stored best move is still utilized for Move Ordering.

5. Theoretical Asymptotics vs. Measured Empirical Reality Unit I — Empirical Analysis

Why Empirical Runtimes Differ from Big-O:

  • Constant Factor Overhead: Hash key creation and dictionary lookup incur a small constant cost (~$1.2\ \mu\text{s}$). For shallow subtrees ($d = 1$), recomputing the leaf heuristic directly can be as fast as table hashing.
  • Transposition Density: Symmetrical midgames yield high cache hit rates ($>20\%$), producing substantial runtime savings. In contrast, narrow forced tactical lines have few transpositions, yielding modest cache hit rates.
  • Hardware & Interpreter Dynamics: CPU instruction caching, memory bus saturation, and Python interpreter bytecode dispatch create non-linear variations across depths.
